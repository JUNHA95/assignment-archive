#### **[1교시] AI Agent 실행 흐름(1교시 부분은 [ ] 내부에 해당함)**

- 사용자 질문 → [요청 분석 → Tool 선택] → Tool 실행(RAG: Rewrite → Retrieve → Rerank → Context → 생성 → 검증 / PostgreSQL: SQL 조회) → 실행 결과 확인 → 최종 응답
- 저번 수업에서 배웠던 RAG 파이프라인을 하나의 Tool로 구성하고, Agent가 요청에 따라 필요한 Tool을 선택하여 실행하는 구조.

#### 1교시 실습 주요 함수

- 요청 분석 담당
• `classify_request()`: 사용자 질문을 분석하여 요청 유형(rag, db, agent)을 분류함.
- Tool 선택 담당
• `plan_for_request()`: `classify_request()`의 반환값을 바탕으로 사용할 Tool을 선택하고 실행 계획을 반환함. 원래는 LLM이 해야하지만, 실습코드에서는 조건문으로 Tool을 선택하고 있음

#### **[2교시] AI Agent 실행 흐름(2교시 부분은 [ ] 내부에 해당함)**

- 사용자 질문 → 요청 분석 → Tool 선택 → [Tool 실행 요청 → Tool 실행 → 실행 결과 전달] → 실행 결과 확인 → 최종 응답
- 1교시 흐름에서 Tool 실행 부분을 조금 더 구체적으로 확인하고 있음

#### 2교시 실습 주요 함수

- Tool 실행 요청 담당
• `make_request()`: 어떤 Tool을 어떤 입력값으로 실행할지 정리 후, 해당 요청에 고유 ID를 부여하여 반환
- 실행 결과 전달 담당
• `match_result()`: `make_request()`가 만든 실행 요청과 실제 Tool 실행 결과를 동일한 ID로 연결하여, 어떤 요청에 대한 결과인지 알 수 있도록 결과 메시지를 구성함.

#### **[3교시] AI Agent에 사용할 Tool 사전준비 간단하게 이해해보기**

- Tool은 AI Agent 실행 흐름 이전에 당연히 미리 구성되어 있는 것이다.
- 이번 실습에서는 2교시 흐름 중 [Tool 실행] 단계를 [입력값 검증 → DB 조회 → 결과 반환]로 구성해본 것.

#### 3교시 실습 주요 함수

- 입력값 검증 담당
• `validate_id()`: 이미 선택된 Tool에 전달된 입력값이 올바른지 검사하는 함수로, 잘못된 입력값으로 DB를 조회하지 않도록 막는 안전장치
- Tool 정의 및 등록 담당
• `register_status_tool()`: 입력값 검증 → DB 조회 → 결과 반환(JSON 문자열)을 수행하는 Tool을 만들고, `@tool`을 이용하여 LangChain Tool로 등록한 뒤 반환하는 함수. 물론 반환된 Tool을 invoke()로 호출해야 실제로 처리가 된다.

#### 주요 용어

- @tool: 일반 Python 함수를 LangChain에서 사용할 수 있는 Tool로 변환함.
- Docstring: Tool이 어떤 기능을 수행하는지 LLM에 알려주는 설명문.

#### **[4교시] AI Agent에 사용할 Tool로, 기존에 구성했었던 RAG를 준비하기**

- 3교시는 간단하게 Tool 준비과정을 살핀 것이고, 4~5교시는 구체적인 Tool을 각각 다르게 준비해본다.
- 흐름: 사용자 질문 → 요청 분석 → Tool 선택 → Tool 실행 요청 → [Tool 실행: 입력값 검증 및 구성 → 기존 RAG 파이프라인 실행 → 결과 반환] → 실행 결과 전달 → 실행 결과 확인 → 최종 응답

#### 4교시 실습 주요 함수

- 입력값 검증 및 구성 담당
• `prepare_search()`: 무엇을 검색할지(질문), 어디에서 검색할지(보고서 카테고리)를 입력받아 올바른 값인지 확인하고, RAG에서 사용할 수 있도록 하나의 딕셔너리로 묶어 반환함.
- RAG 파이프라인 실행 담당
• `invoke_rag()`: `prepare_search()`에서 준비한 질문과 카테고리를 기존 RAG 함수(`rag_answer()`)에 전달하여 관련 보고서를 검색하고, 답변을 생성한 뒤 그 결과를 반환함. 아직 `@tool`을 이용한 Tool 등록은 하지 않아서 Agent가 직접 호출할 수는 없고, 우리가 직접 호출해야 하는 상황이다. 나중에 Agent가 사용할 RAG 기능을 사전에 정상작동하는지 확인하기 위한 것이라고 생각하면 된다.

#### **[5교시] AI Agent에 사용할 Tool로, 기존에 구성했었던 PostgreSQL 조회기능을 준비하기**

- 4교시의 RAG도 안전성이 필요하지만, 5교시에서는 특히 DB의 데이터를 변경하지 않고 안전하게 조회할 수 있도록 읽기 전용(Read-only) 권한과 조회 조건의 설정을 강조함
- 흐름: 사용자 질문 → 요청 분석 → Tool 선택 → Tool 실행 요청 → [Tool 실행: 입력값 검증 → DB 조회 → 조회 결과 정리 및 반환] → 실행 결과 전달 → 실행 결과 확인 → 최종 응답

#### 5교시 실습 주요 함수

- 입력값 검증 담당
• `parse_report_id()`: 조회하려는 보고서 ID가 올바른 값인지 검사하고, DB 조회에 사용할 수 있도록 정수로 반환함.
- DB 조회 담당
• `fetch_report_status()`: `parse_report_id()`에서 반환한 보고서 ID를 이용하여 기존 PostgreSQL에서 해당 보고서의 상태를 조회함. 4교시와 마찬가지로 아직 Tool 등록은 안 할 것이라, 실습 코드들은 우리가 직접 호출하는 상황이다.
- 조회 결과 정리 및 반환 담당
• `status_view()`: DB에서 조회한 결과를 받아 보고서가 존재하는지 확인하고, 존재한다면 보고서 ID, 인덱싱 상태, 수정 버전, 벡터의 최신 여부만 정리하여 반환함.

#### [6교시] 구성했던 RAG와 PostgreSQL Tool을 하나의 Agent로 연결하여 실제 agent 만들기

- 사전 구성: RAG Tool + PostgreSQL Tool + LLM + 행동 규칙 + 안전장치 → `create_agent()` → AI Agent 구성
- 전체 흐름(`agent.invoke()`로 한 방에 전체 흐름 작동): [사용자 질문 → 요청 분석 → Tool 선택 → Tool 실행 요청 → Tool 실행 → 실행 결과 전달 → 실행 결과 확인 → 최종 응답]
- 이번 교시부터는 Python 조건문이 아닌 실제 LLM이 필요한 Tool을 판단하고 호출을 요청하는 단계로, 요약하자면, `create_agent()`로 Agent를 구성하고 `agent.invoke()`로 Agent를 실행하는 것.

#### 6교시 실습 주요 함수

- AI Agent 구성 담당
• `make_agent()`: 사용할 LLM, RAG 및 PostgreSQL Tool, 행동 규칙, 안전장치를 `create_agent()`에 전달하여 하나의 AI Agent로 구성하고 반환함.
- AI Agent 실행
• `agent.invoke()`: 준비한 사용자 질문을 Agent에 전달하여 요청 분석부터 최종 응답까지의 전체 과정을 실행함.

#### AI Agent 구성요소

| 구성 요소 | 역할 |
| --- | --- |
| `model` | 요청을 분석하고 Tool을 선택하며 답변을 생성할 LLM |
| `tools` | LLM이 선택하여 사용할 수 있는 Tool 목록 |
| `system_prompt` | LLM이 따라야 할 행동 및 답변 규칙 |
| `middleware` | Agent 실행 과정에서 작동하는 안전장치(이번 실습에서는 Tool 호출 최대 4회, 모델 호출 최대 6회) |

#### [7교시] AI Agent 안전장치 구성하기

- 사용자 질문 → 요청 분석 → Tool 선택 → Tool 실행 요청 → [Tool 실행: 입력값 검증 → 실제 처리 → 오류 발생 시 오류 분류] → 실행 결과 전달 → 실행 결과 확인 → 최종 응답
- 잘못된 입력값으로 Tool이 실행되는 것을 방지하고, 오류가 발생하면 그 유형을 구분하는 실습

#### 7교시 실습 주요 함수

- 입력값 검증 담당
• `validate_report_id()`: 입력받은 보고서 ID가 올바른 값인지 검사하고, 정상이라면 정수로 반환하며 잘못된 값이라면 오류를 발생시킴.
- 오류 분류 담당
• `classify_error()`: 발생한 오류를 전달받아 입력값 문제인지, 그 외 Tool 실행 문제인지 구분하여 반환

#### 오류 유형

| 오류 코드 | 의미 |
| --- | --- |
| `INVALID_ARGS` | 잘못된 입력값으로 인한 오류로 분류함(`ValueError`) |
| `TOOL_FAILURE` | 그 외 Tool 실행 과정에서 발생한 오류 |

#### [8교시] AI Agent를 FastAPI 서비스로 연결하기

- 사용자 질문 → FastAPI → AI Agent(run_agent()로 기존 흐름 실행) → FastAPI → 응답 반환
- 접수 FastAPI 역할: 요청 접수 및 입력값 검증
- 반환 FastAPI 역할: 최종 결과 확인 및 응답 구성

#### 8교시 실습 주요 함수

- FastAPI 구성 담당
• `make_api()`: 사용자 질문을 접수하고 Agent에 전달한 뒤 결과를 반환할 수 있도록 API를 구성함.
- 요청 접수 및 처리 담당
• `ask()`: 사용자의 질문을 받아 `run_agent()`와 `api_response()`를 순서대로 실행함.
- AI Agent 실행 담당
• `run_agent()`: 사용자 질문을 전달받아 요청 분석부터 최종 응답까지 Agent의 전체 실행 과정을 진행함.
- 최종 결과 확인 및 응답 구성 담당
• `api_response()`: Agent의 실행 완료 여부와 출처 검증 결과를 확인하고 API 응답 형식으로 정리하여 반환함.

#### 오류 처리

| HTTP 상태 코드 | 의미 |
| --- | --- |
| 422 | 잘못된 입력값 |
| 403 | 접근 권한 위반 |
| 502 | Agent 결과·출처 검증 실패 등 `RuntimeError` 발생 |
| 503 | 그 외 실행 오류 |
