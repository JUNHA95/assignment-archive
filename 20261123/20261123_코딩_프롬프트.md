## 실습 04 — Hit을 Document로 변환

### 1. `to_document()`

**[목적]**

검색된 Hit 한 건을 LangChain의 Document 객체로 변환한다.

**[입력]**
- `hit` (`dict`): 7개의 Key를 가진 Hit 한 건
- `body`: 문서 본문
- 나머지 6개 Key: 문서 ID, 버전, 원문 위치 등의 출처 정보

**[처리]**
1. Hit에서 `body` 값을 추출한다.
2. `METADATA_KEYS`에 정의된 6개 Key와 값을 딕셔너리로 구성한다.
3. `Document()`를 이용해 본문과 Metadata를 저장한다.

**[출력]**
- `Document` 객체 1개
- `page_content`: Hit의 `body`
- `metadata`: Hit의 나머지 6개 Key와 값

**[구현 조건]**
1. 기존 `langchain_core.documents.Document`를 사용한다.
2. `METADATA_KEYS`에 정의된 6개 Key를 사용한다.
3. 원본 데이터의 값과 자료형을 유지한다.
4. 검색, 데이터 수정, 추가 검증 기능을 구현하지 않는다.
5. 해당 함수의 TODO 부분만 수정한다.

**[구현 코드]**

```python
def to_document(hit: dict) -> Document:
    # 1. Hit에서 본문 추출
    body = hit["body"]

    # 2. Metadata 구성
    metadata = {key: hit[key] for key in METADATA_KEYS}

    # 3. Document 객체 생성 및 반환
    return Document(
        page_content=body,
        metadata=metadata
    )
```

### 2. `hits_to_documents()`

**[목적]**

여러 Hit을 각각 Document 객체로 변환하고 목록으로 반환한다.

**[입력]**
- `hits` (`list[dict]`): Hit 딕셔너리 목록

**[처리]**
1. 변환된 Document를 저장할 빈 목록을 만든다.
2. 입력된 Hit을 순서대로 하나씩 가져온다.
3. 기존 `to_document()`를 호출하여 변환한다.
4. 변환된 Document를 목록에 추가한다.
5. 완성된 목록을 반환한다.

**[출력]**
- `list[Document]`: 변환된 Document 목록
- 빈 입력이면 `[]` 반환

**[구현 조건]**
1. 기존 `to_document()` 함수를 재사용한다.
2. 입력 순서를 유지한다.
3. 빈 목록에서는 가짜 Document를 생성하지 않는다.
4. 원본 본문과 Metadata를 변경하지 않는다.
5. 검색, 정렬, 중복 제거, 추가 검증을 구현하지 않는다.
6. 해당 함수의 TODO 부분만 수정한다.

**[구현 코드]**

```python
def hits_to_documents(hits: list[dict]) -> list[Document]:
    # 1. 빈 목록 준비
    documents = []

    # 2. Hit을 순서대로 변환
    for hit in hits:
        document = to_document(hit)
        documents.append(document)

    # 3. Document 목록 반환
    return documents
```

**실습 핵심:** Hit 목록 → 개별 Document 변환 → Document 목록 반환

## 실습 05 — Prompt 구성과 Chat Model 호출

### 1. `make_inputs()`

**[목적]**

사용자 질문과 Context를 Prompt에 전달할 수 있도록 딕셔너리로 구성한다.

**[입력]**
- `question` (`str`): 사용자 질문
- `context` (`str`): 답변에 사용할 참고 자료

**[처리]**
1. `question`과 `context`를 각각 같은 이름의 Key에 연결한다.
2. 두 값을 하나의 딕셔너리로 구성한다.
3. 완성된 딕셔너리를 반환한다.

**[출력]**
- `dict`: `{"question": question, "context": context}`

**[구현 조건]**
1. Key 이름은 Prompt 변수인 `"question"`, `"context"`와 일치해야 한다.
2. 입력 문자열을 변경하지 않는다.
3. 기존 함수 이름과 매개변수를 유지한다.
4. 해당 함수의 TODO 부분만 수정한다.

**[구현 코드]**

```python
def make_inputs(question: str, context: str) -> dict:
    return {
        "question": question,
        "context": context
    }
```

### 2. `invoke_pair()`

**[목적]**

Prompt를 실행하여 완성된 입력을 만들고, Chat Model에 전달하여 답변을 생성한다.

**[입력]**
- `prompt`: 질문과 Context를 정해진 형식으로 구성하는 객체
- `chat_model`: 답변을 생성하는 모델
- `inputs` (`dict`): `make_inputs()`에서 준비한 입력값

**[처리]**
1. `prompt.invoke(inputs)`로 Prompt를 구성한다.
2. 생성된 `prompt_value`를 `chat_model.invoke()`에 전달한다.
3. Chat Model의 응답을 `message`에 저장한다.
4. 두 결과를 반환한다.

**[출력]**
- `prompt_value`: 완성된 Prompt
- `message`: 모델이 생성한 응답
- 두 값을 튜플로 반환한다.

**[구현 조건]**
1. Prompt를 먼저 실행하고 Chat Model을 나중에 실행한다.
2. 첫 번째 `invoke()`의 반환값을 두 번째 `invoke()`의 입력으로 사용한다.
3. 두 단계의 결과를 모두 반환한다.

**[구현 코드]**

```python
def invoke_pair(prompt, chat_model, inputs: dict):
    # 1. Prompt 구성
    prompt_value = prompt.invoke(inputs)

    # 2. 모델 호출 및 답변 생성
    message = chat_model.invoke(prompt_value)

    # 3. 두 결과 반환
    return prompt_value, message
```

**실습 핵심:** 입력 준비 → Prompt 구성 → LLM 답변 생성 → 결과 기록

## 실습 06 — Context 구성과 Runnable Chain 실행

### 1. `prepare_context()`

**[목적]**

검색된 Document 목록으로 Context를 구성하고, 출처 정보와 함께 Prompt에 전달할 입력값을 준비한다.

**[입력]**
- `documents`: 검색된 Document 목록
- `question` (`str`): 사용자 질문
- `max_items=2`: Context에 포함할 최대 문서 개수
- `max_chars=600`: Context의 최대 문자 수

**[처리]**
1. `build_context()`로 Context와 포함된 Document 목록을 얻는다.
2. 포함된 Document의 Metadata에서 `citation_id`를 추출한다.
3. 질문과 Context를 Prompt 입력용 딕셔너리로 구성한다.
4. Context, 출처 ID, 포함된 Document, Prompt 입력값을 묶는다.

**[출력]**
- `context` (`str`): 구성된 Context
- `provided_ids` (`list[int]`): 포함된 문서의 출처 ID 목록
- `included_docs` (`list[Document]`): 실제 포함된 Document 목록
- `inputs` (`dict`): 질문과 Context를 담은 Prompt 입력값

**[구현 조건]**
1. 기존 `build_context()`를 사용한다.
2. `max_items`, `max_chars`를 전달한다.
3. 출처 ID는 `included_docs`에서만 추출한다.
4. 사용자 질문을 변경하지 않는다.
5. 지정된 네 개의 Key를 가진 딕셔너리를 반환한다.
6. 해당 함수만 수정한다.

**[구현 코드]**

```python
def prepare_context(documents, question: str, max_items=2, max_chars=600) -> dict:
    # 1. Context 구성
    context, included_docs = build_context(
        documents, max_items=max_items, max_chars=max_chars
    )

    # 2. 출처 ID 추출
    provided_ids = [doc.metadata["citation_id"] for doc in included_docs]

    # 3. Prompt 입력 준비
    inputs = {
        "question": question,
        "context": context
    }

    # 4. 결과 반환
    return {
        "context": context,
        "provided_ids": provided_ids,
        "included_docs": included_docs,
        "inputs": inputs
    }
```

### 2. `run_generation()`

**[목적]**

Prompt와 Structured Model을 Runnable Chain으로 연결하고 실행 결과를 반환한다.

**[입력]**
- `prompt`: 질문과 Context를 구성하는 객체
- `structured_model`: 정해진 구조로 응답하는 모델
- `inputs` (`dict`): 질문과 Context를 담은 입력값

**[처리]**
1. `|` 연산자로 Prompt와 Structured Model을 연결한다.
2. `chain.invoke(inputs)`로 Chain을 실행한다.
3. 반환된 `bundle`을 그대로 반환한다.

**[출력]**
- `bundle` (`dict`): 모델 실행 결과
- `raw`: 원본 응답
- `parsed`: 구조화된 응답
- `parsing_error`: 변환 오류 또는 `None`

**[구현 조건]**
1. `prompt | structured_model` 순서로 연결한다.
2. 앞 단계의 출력을 뒤 단계의 입력으로 전달한다.
3. `inputs`를 사용하여 실행한다.
4. `bundle`의 세 필드를 수정하지 않는다.
5. 해당 함수만 수정한다.

**[구현 코드]**

```python
def run_generation(prompt, structured_model, inputs: dict):
    # 1. Runnable Chain 구성
    chain = prompt | structured_model

    # 2. Chain 실행
    bundle = chain.invoke(inputs)

    # 3. 결과 반환
    return bundle
```

**실습 핵심:** Context 준비 → Prompt 구성 → 모델 실행 → 구조화된 응답 반환 → 결과 기록

## 실습 07 — Citation 및 응답 검증

### 1. `allowed_source_ids()`

**[목적]**

Context에 실제 포함된 Document에서 출처 ID를 추출하여 Citation 검증에 사용할 허용 ID 집합을 만든다.

**[입력]**
- `included_docs`: Context 구성에 실제 사용된 Document 목록

**[처리]**
1. 각 Document에 접근한다.
2. `metadata["citation_id"]`를 추출한다.
3. 추출한 ID를 중복 없이 집합으로 구성한다.

**[출력]**
- `set[int]`: 허용된 출처 ID 집합

**[구현 조건]**
1. `included_docs`에서만 ID를 추출한다.
2. ID의 자료형을 변경하지 않는다.
3. 중복된 ID는 집합으로 제거한다.
4. Document와 Metadata를 변경하지 않는다.
5. 해당 함수만 수정한다.

**[구현 코드]**

```python
def allowed_source_ids(included_docs):
    # Context에 포함된 문서의 출처 ID를 집합으로 반환
    return {doc.metadata["citation_id"] for doc in included_docs}
```

### 2. `inspect_case()`

**[목적]**

`receive_bundle()`로 응답과 출처를 검증하고 성공 또는 실패 결과를 기록할 딕셔너리를 구성한다.

**[입력]**
- `case`: 검증할 사례 이름과 응답 Bundle
- `provided_ids`: Context에 실제 포함된 출처 ID 집합

**[처리]**
1. `receive_bundle()`에 Bundle과 허용 출처 ID를 전달한다.
2. 검증에 성공하면 `KnowledgeAnswer`를 딕셔너리로 변환한다.
3. `RagServiceError`가 발생하면 오류 내용을 문자열로 저장한다.
4. 성공 또는 실패 결과를 반환한다.

**[출력]**
- `case`: 검증 사례 이름
- `outcome`: `"accepted"` 또는 `"rejected"`
- `error`: 성공 시 `None`, 실패 시 오류 코드
- `result`: 성공 시 검증된 답변 딕셔너리, 실패 시 `None`
- `human_review_required`: 성공 시 `True`, 실패 시 `False`

**[구현 조건]**
1. 기존 `receive_bundle()`의 검증 규칙을 사용한다.
2. 성공 시 `answer.model_dump()`를 사용한다.
3. 실패 시 `str(exc)`로 오류 코드를 저장한다.
4. 성공과 실패 모두 지정된 다섯 개의 Key를 반환한다.
5. 성공 시 사람의 원문 대조가 필요하므로 `human_review_required=True`로 설정한다.
6. 실패 시 `human_review_required=False`로 설정한다.
7. 해당 함수만 수정한다.

**[구현 코드]**

```python
def inspect_case(case, provided_ids):
    # 1. 응답과 출처 검증
    try:
        answer = receive_bundle(case["bundle"], provided_ids)

        # 2. 검증 성공
        return {
            "case": case["name"],
            "outcome": "accepted",
            "error": None,
            "result": answer.model_dump(),
            "human_review_required": True
        }

    # 3. 검증 실패
    except RagServiceError as exc:
        return {
            "case": case["name"],
            "outcome": "rejected",
            "error": str(exc),
            "result": None,
            "human_review_required": False
        }
```

**실습 핵심:** 허용 출처 ID 준비 → 응답의 출처 및 형식 검증 → 성공·실패 결과 기록
