Day23 — AI 시스템 전체 구조 정리
전체 흐름: 사용자 질문 → 관련 자료 검색 → AI 답변 생성 → 결과 검증 → 사용자에게 응답

※ 각 단계에 [필수], [사전 준비], [검색 시], [선택], [오류 발생 시]를 표시하여 실제 실행 여부를 구분함.
1. 사용자 [필수]
- 사용자가 궁금한 내용을 질문함.
- 예: "서버는 어디에서 실행하나요?"
- 질문을 FastAPI에 전달함.
2. FastAPI [필수]
- 사용자의 질문을 받아 처리하는 서버 역할.
- 질문을 검색 및 AI 답변 생성 과정에 연결함.
- 처리 결과를 최종적으로 사용자에게 전달함.
3. PostgreSQL [사전 준비 + 검색 시]
- AI가 참고할 문서의 원문과 정보를 저장하는 데이터베이스.
- 문서 ID, 내용, 분류 등의 데이터를 미리 저장함.
- 검색이 필요할 때 저장된 자료를 제공함.
4. Embedding [사전 준비 + 검색 시]
- 문서와 질문의 의미를 숫자 목록(벡터)으로 변환함.
- 문서는 미리 변환해 두고, 사용자 질문은 검색할 때 변환함.
- 이렇게 만든 숫자를 이용하면 질문과 문서의 의미를 비교할 수 있음.
5. pgvector [사전 준비 + 검색 시]
- PostgreSQL에서 벡터를 저장하고 검색하도록 도와주는 확장 기능.
- 미리 만들어 둔 문서 벡터를 저장함.
- 검색 시 질문 벡터와 문서 벡터의 거리를 계산함.
6. Retriever [검색 시]
- 질문과 관련 있는 문서를 찾아주는 검색기.
- Embedding과 pgvector를 이용해 가까운 문서를 Top-K 방식으로 선택함.
- 검색된 문서의 원문, ID, 거리 등을 다음 단계로 전달함.
7. 검색 결과 평가 [선택: 개발·검증 시]
- 검색된 문서가 실제 질문과 얼마나 관련 있는지 평가함.
- 사람이 미리 만든 Gold 기준으로 관련, 부분 관련, 무관을 구분함.
- 검색 품질을 확인하기 위한 과정으로, 모든 사용자 요청마다 실행할 필요는 없음.
8. Context 구성 [검색 자료 활용 시]
- 검색된 자료 중 답변에 필요한 내용을 선택함.
- 선택된 원문을 AI가 참고할 자료(Context)로 정리함.
- AI가 질문에 답할 때 사용할 근거를 준비하는 과정임.
9. Prompt 조립 [필수]
- 사용자 질문, 참고자료(Context), 지시사항을 하나로 합침.
- AI가 무엇을 참고하고 어떤 형식으로 답변해야 할지 지정함.
- 완성된 Prompt를 LLM에 전달함.
10. LLM Client [필수]
- 완성된 Prompt를 AI 모델(LLM)에 전달함.
- AI 모델이 질문과 참고자료를 바탕으로 답변을 생성함.
- 생성된 답변을 받아 다음 검사 단계로 전달함.
11. 출력 검사 [필수]
- AI가 생성한 답변이 정해진 형식을 지켰는지 확인함.
- 예: 필요한 ID나 근거 정보가 포함되어 있는지 검사함.
- 형식이 올바르면 다음 단계로, 잘못되면 실패 처리로 연결함.
12. 근거 검토 [검증 과정]
- AI가 작성한 답변을 실제 원문과 비교함.
- 답변의 내용이 제공된 자료로 뒷받침되는지 확인함.
- 검토를 통과하면 FastAPI를 통해 사용자에게 전달함.
13. 실패·중단 [오류 발생 시]
- 데이터베이스 연결 실패, LLM 통신 오류, 출력 형식 오류 등이 발생하면 실행됨.
- 오류 종류와 원인을 기록하고 문제가 있는 처리를 중단함.
- 정상적인 답변으로 전달하지 않고 필요한 오류 정보를 반환함.
